Press Release
Emode launches a universal Virtual Try-On + Dressing Room that installs on Shopify, embeds on any site, and works across the web via Chrome
New York, NY — Emode today announced the launch of a universal Virtual Try-On and Dressing Room platform that lets shoppers visualize clothing on their own body before purchasing. Emode installs as a Shopify Theme App Extension, ships as a copy-paste embeddable widget for non-Shopify retailers, and operates across the open web through a Chrome extension.
Shoppers can click Try This On or Add to Dressing Room on product pages, open a modern white & black with gray accented modal, upload/take a photo, and generate a realistic try-on image. Shoppers can then compose outfits, swap items, save (“star”) items and looks for later, and purchase through native cart insertion on Shopify or outbound links elsewhere.
Merchants get a dashboard with analytics, bulk product ingestion, and asset-quality warnings that ensure try-ons render reliably and convert.

5) What are the exact APIs and request/response formats?
All requests validated with Zod and require an auth context:
Consumer auth: Supabase session JWT


Merchant auth: Supabase session (merchant member) or Shopify signed session


5.1 Create/Update user profile photo
POST /api/profile/photo
Body: multipart/form-data (image)


Output: { faceImageUrlSigned, updatedAt }


5.2 Get generation limits
GET /api/usage
Output:


{
  "date": "2025-12-20",
  "limit": 5,
  "used": 2,
  "remaining": 3,
  "isPro": false
}
5.3 Generate single-item try-on
POST /api/tryon/single
Body:


{
  "merchantId": "uuid",
  "shopDomain": "myshop.myshopify.com",
  "product": {
    "platform": "shopify",
    "productId": "123",
    "variantId": "456",
    "title": "Classic Hoodie",
    "imageUrl": "https://cdn.shopify.com/..."
  },
  "userImage": {
    "source": "upload|camera|stored",
    "uploadPath": "user_uploads/..."
  },
  "bodyParams": {
    "heightIn": 70,
    "weightLb": 175,
    "fit": "regular|slim|oversized"
  },
  "category": "hoodie"
}
Output:


{
  "generationId": "uuid",
  "status": "queued",
  "pollUrl": "/api/tryon/status?generationId=uuid"

9) How are generation limits enforced exactly?
Enforcement is server-side (cannot be bypassed reliably client-side).
On every generation request:
Resolve user identity:


Supabase JWT (logged in)


guest session id (cookie) if allowed


Look up entitlement:


entitlements row


Read usage_counters for today


If used >= limit and not unlimited:


reject with HTTP 402 (Payment Required) style error


If allowed:


increment usage counter transactionally


create generations row queued


enqueue job
